CODE CAMPUS — SIMPLE HTML / CSS / JAVASCRIPT GUIDE
==================================================

WHY HTML IS USED
----------------
HTML is the structure of the website. It tells the browser what each part means and
where it belongs. CSS makes those parts look good. JavaScript is only needed when
the page must change something dynamically that HTML and CSS cannot do by themselves.

THE THREE MAIN TECHNOLOGIES
---------------------------
1. HTML — STRUCTURE AND CONTENT
   - <html>, <head> and <body> form the document. The head holds the title, metadata
     and links to CSS/JavaScript files; the body holds what visitors see.
   - <header> and <nav> hold the logo and navigation.
   - <main> marks the main content of a page.
   - <section>, <article> and <aside> group related content.
   - <h1> to <h3> create headings. <p> creates paragraphs.
   - <div> groups elements when no more specific semantic element is needed.
   - <span> groups a small piece of inline text.
   - <a href="page.html"> is a normal link to another page. It works without JS.
   - <button> represents an action. type="button" does not submit a form;
     type="submit" submits its associated form.
   - <label for="some-id"> connects visible label text to an input with that ID.
   - <input> creates text, email, password, checkbox and radio controls.
   - <textarea> creates a multi-line message field.
   - <form> groups controls for native browser validation and submission.
   - required tells the browser a value must be entered. type="email" asks the
     browser to check basic email-address formatting.
   - <pre><code> displays code while preserving spaces and line breaks.
   - <details><summary> makes an expandable section without JavaScript.
   - <iframe> embeds an external page, such as the OneCompiler editor.
   - <svg> contains vector icons. SVG icons do not need JavaScript.

   IMPORTANT HTML ATTRIBUTES USED HERE
   - class: connects an element to CSS rules. Many elements can share one class.
   - id: gives one element a unique identifier. Labels, links and form associations
     can refer to that identifier. IDs should not be duplicated on a page.
   - href: destination of a link.
   - src: file or website loaded by an image, script or iframe.
   - type: tells the browser what kind of input or button it is.
   - required: activates built-in browser validation.
   - autocomplete: hints whether the browser should offer saved input values.
   - aria-label / aria-labelledby: adds an accessible name for assistive technology.
   - alt: text alternative for an image.
   - loading="lazy": lets the browser defer loading an iframe until it is needed.

2. CSS — DESIGN AND LAYOUT
   CSS controls how the HTML looks. In this project it handles:
   - fonts, font sizes, colours and text alignment;
   - gradients, glassmorphism, blur, borders, shadows and rounded corners;
   - card layouts, spacing, grid/flex positioning and responsive sizing;
   - hover and keyboard-focus styles;
   - mobile breakpoints using @media;
   - the hamburger menu using :checked on its checkbox;
   - navigation glider positions using :checked radio markers;
   - light and dark visual rules using html[data-theme="light"] and [data-theme="dark"].

   Common CSS terms:
   - .class selects every element with that class.
   - #id selects the one element with that ID.
   - :hover applies while a pointer is over an element.
   - :focus-visible applies when an element receives keyboard focus.
   - :checked applies to selected checkboxes/radio buttons.
   - @media changes rules at certain screen widths or device preferences.
   - display:flex and display:grid arrange elements into layouts.
   - backdrop-filter:blur(...) blurs what is behind a translucent element.
   - transition animates a CSS property change.

3. JAVASCRIPT — ONLY TWO SMALL FEATURES
   There are only two JavaScript files in this package.

   theme.js — dark/light switch
   - Reads the saved theme from localStorage.
   - If the visitor has not chosen a theme before, it follows the device preference.
   - Adds data-theme="light" or data-theme="dark" to the <html> element.
   - theme.css sees that attribute and applies the matching colours and backgrounds.
   - When the theme button is clicked, the script switches the value and saves it.
   - If JavaScript is disabled, the site still displays in its dark fallback theme,
     but the theme button cannot switch modes.

   compiler-run.js — extra Run button for narrow screens
   - Finds the OneCompiler iframe and its title bar.
   - Adds a small Run button. compiler-run.css displays it only at widths of 780px
     or less.
   - When clicked, it sends OneCompiler the triggerRun message.
   - On wider screens, use the Run control inside OneCompiler itself.
   - If JavaScript is disabled, this extra mobile button is not added. The embedded
     editor still loads, but on a phone you may not have a visible Run control if
     OneCompiler hides its own control at that screen size.

HOW THE WEBSITE PARTS WORK
--------------------------
Navigation and header
- Navigation items are ordinary <a href> links. The browser opens the page named
  in href; JavaScript is not involved.
- The hidden radio inputs beside those links are visual state markers for the
  sliding glider. CSS moves the glider to the selected position.
- On small screens, a checkbox and its label form the hamburger toggle. CSS uses
  .menu-toggle:checked ~ .nav-dropdown to show/hide the menu. No JS is needed.

Home page
- index.html is the home page. It contains both the original light and dark template
  containers. theme.css shows the chosen one when theme.js runs. Without JS, the dark
  template is displayed as the fallback.

Tutorials
- tutorials.html is the course overview.
- tutorials-1.html through tutorials-6.html are six Python lessons.
- html-css-1.html through html-css-6.html are six HTML/CSS lessons.
- Lesson text, headings, code samples, tips and next/previous links are HTML.
- The code examples are static text. Copy the relevant example manually into the
  OneCompiler iframe and press Run. The old lesson.js auto-load/copy/reset feature
  has been removed to avoid JavaScript dependency.
- For an HTML + CSS example, put the HTML in index.html and CSS in style.css inside
  the OneCompiler workspace.

Practice pages
- practice.html shows three practice cards. Each card is a normal link.
- The links open practice-html.html, practice-html-css.html or practice-python.html.
- Each workspace has task instructions, starter code inside an expandable <details>
  section, and an embedded OneCompiler editor.
- Copy the starter code into the editor manually. The old practice.js auto-fill and
  reset controls have been removed.
- For HTML + CSS practice, create a second file named style.css in OneCompiler.

Contact form — native HTML only, no data is sent
- The name input has id="name", type="text" and required.
- The email input has id="email", type="email" and required.
- The message field has id="mesg" and required.
- Their labels use for="name", for="email" and for="mesg" so clicking a label
  focuses its matching field.
- These controls are associated with the form using form="contactForm".
- The category radio pills remain a separate radio group and are not part of the form.
- The form uses action="./thank-you.html" and method="get". The text fields have
  no name attributes, so their values are not included in the request URL. The topic
  radios are not form-associated either. After the browser validates all three
  required fields and the email format, the browser simply opens thank-you.html.
- No JavaScript runs for this form. No email, name or message is sent, stored or
  delivered to anyone. The thank-you page is only a confirmation screen.

Login page — visual-only preview
- login.html shows the sign-in design, but it is not a real login form.
- It does not submit credentials, check a password, create an account or store data.
- The Sign In button is disabled. The inputs are only there to show the design.
- The password visibility control and authentication script were removed because
  there is no real authentication behaviour to support.

OneCompiler editor
- Code Campus does not execute Python or HTML/CSS itself. The iframe loads OneCompiler.
- OneCompiler runs the code within its own service. An internet connection is required.
- The desktop Run button belongs to OneCompiler. The small extra Run button is only
  a convenience for narrow screens.

OTHER COMPONENTS AND FILES
--------------------------
- Bootstrap CSS: provides common layout helpers such as .container, .row, .col,
  spacing and responsive utilities. The pages use its stylesheet; the Bootstrap JS
  bundle is not loaded because the website does not need Bootstrap JS components.
- Google Fonts: loads Plus Jakarta Sans. If the network is unavailable, the browser
  uses the fallback sans-serif font.
- style.css: an existing stylesheet referenced by the pages. It was not in the files
  supplied for this update, so keep the original file in the website folder.
- images/: contains the logo and other images referenced by the pages. This folder
  was not included in the uploaded source files; keep your original images folder.
- theme.css: light/dark visual overrides. It does not change the HTML structure.
- style_1.css: main custom layout, navigation, mobile menu and general design.
- cards.css: course and practice card layouts.
- lesson.css: tutorial lesson layout and code samples.
- contact.css: contact page layout.
- auth.css: login preview styling.
- compiler-run.css: display and styling for the small-screen Run button.
- practice-pages.css: separate practice workspace styling.

NO-JAVASCRIPT REALITY CHECK
---------------------------
The website content, normal page links, mobile menu, contact validation, confirmation
redirect, expandable examples and responsive layout work without JavaScript. The theme
switch and the extra small-screen compiler Run control need JavaScript. OneCompiler itself
needs an internet connection.
